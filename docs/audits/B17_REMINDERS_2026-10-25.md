# B17 personal deadline reminders

Status: deployed and enabled on October 25, 2026 through PR #353. Working tree:
`C:\Projects\ArtSoul`, `codex/takeover-audit`, release HEAD `1392b5b`.
This completes the personal-reminder implementation slice, not all B17 or Phase B.

## Approved behavior

The founder approved one reminder one hour before a deadline by default, with
up to three personal reminder times within 24 hours. This slice supports unique
whole-minute offsets from 1 to 1,440, including fractional hours that resolve to
whole minutes. The same schedule covers auction end and payment deadline; users
can switch reminders off without losing their schedule. Settings remain private.

The creator and recorded bidders receive auction-ending reminders. Only the
recorded winner receives payment-deadline reminders. Saved does not subscribe a
wallet. These are in-app notices checked while Notifications is open, not email,
push, background delivery or guaranteed alarms. No contract/economic amendment.

## Implementation boundaries

- Reuse the existing private inbox, outbox and read-state/preferences tables.
  A new opt-in v3 capability preserves v1/v2 clients and their preference writes.
- Read-time materialization avoids a new worker. A first-page request inserts at
  most 21 idempotent candidate rows, with at most 20 current reminders displayed.
  Historical pagination stays independent. Older-page reads do not insert.
- Source-proven confirmed Core events reconstruct the current round, extension,
  ending, winner and settlement. Mutable auction parent projections alone cannot
  resurrect an old deadline after rewind. Latest rows are selected before source
  validation, so an unknown newer event cannot revive an older valid deadline.
- A creation-event correlation supports rollback cleanup. Dynamic validation
  also excludes a reverted bid, extension or ending that leaves that correlation
  in place. The chain revision is locked against concurrent rollback.
- Each auction/kind/wallet/offset has one durable identity. Extensions keep that
  identity/read state and move the visible deadline. Only the most recent due
  offset is shown when someone returns after several reminder times have passed.
- The indexed boundary block and heartbeat must both satisfy the existing
  120-second healthy limit. Unavailable current reminders do not erase history.
  Live rehearsal found that the existing empty-range optimization omitted these
  headers. The worker now retains the range boundary alongside event blocks,
  deduplicated, instead of fetching every empty block. A missing/failed header
  still fails freshness validation; no timestamp is synthesized.
  Client refresh is bounded to visible/open notifications, with focus resume;
  current rows expire locally at their deadline or after 60 seconds without fresh
  evidence, using server time plus elapsed request time, not device wall time.
- Reminder links open the artwork for current state. No automatic payment or
  claim is introduced. Source transaction hashes refer to actual indexed events.

## Interpretation record

The approved personal times are whole-minute offsets of 1–1,440 minutes, shared
by both deadline categories; fractional hours are accepted only when they resolve
to whole minutes. Returning after several offsets shows the latest due reminder,
not a burst of missed notices. These display/delivery decisions do not alter
auction durations, settlement deadlines or economics.
