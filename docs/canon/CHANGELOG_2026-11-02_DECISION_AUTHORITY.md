# Current decisions and document evolution

## Founder clarification

On November 2, 2026, the founder reiterated that the Bible and canon contain
outdated decisions and must not prevent improvements based on current product
needs and professional practice. This clarifies decision authority and workflow;
it does not select new economic values or change deployed contract behavior.

## Working rule

1. Current founder instructions and accepted decisions supersede conflicting
   older documentation. Preserve the useful baseline and explain material changes.
2. UI, copy, accessibility, layout, performance and routine engineering choices
   are delegated within the authorized task. Missing or obsolete canon wording
   is not a reason to stop, downgrade the result or request repeated permission.
3. Use current authoritative sources, actual product behavior and measured
   verification. Compare usability, security, maintainability and cost. A pattern
   used by a popular project is a candidate, not proof that it fits ArtSoul.
4. Continue already authorized contract and integration design. Reuse specific
   prior approvals. Ask only for a consequential unresolved choice, such as a new
   financial parameter, custody or spending authority, when it cannot reasonably
   be inferred from those approvals. Continue independent work meanwhile.
5. Distinguish intended direction, proposal, implementation, deployment and
   verified acceptance. Documents cannot make an unimplemented feature live.
6. Keep work bounded and traceable. Prioritize current requests, incidents and
   real dependencies. Independent later-phase preparation does not require
   pretending that unfinished earlier acceptance gates have passed.
7. Reconcile superseded documents in the same change or an explicit follow-up.
   This is recordkeeping, not a separate approval gate for authorized work.

## Independent operating limits

The standing prohibition on extra paid services and billable overages remains.
Do not disable spend caps, raise paid tiers or treat new API keys as extra account
quota. General modernization does not authorize mainnet writes, new credential
exposure, destructive data resets or financial signing. Specific existing
permissions retain their stated scope. Preserve data, secrets and project
isolation, and report real provider/access limitations honestly.

Both founder-selected palettes and static Classic feedback remain current
design preferences. This clarification does not silently replace them.
